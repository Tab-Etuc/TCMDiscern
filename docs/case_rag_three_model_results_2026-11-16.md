# Case-RAG H200：S1／S2／S3 三模型 300 筆 Dev Pilot 實驗分析

日期：2026-11-16
來源：專案根目錄 `case_rag_reports.tar.gz`（9 份 JSON）；`experiments/case_rag_aggregate_2026-11-16.json`
重現：`.venv/bin/python -m scripts.analyze_case_rag_archive case_rag_reports.tar.gz --save experiments/case_rag_aggregate_2026-11-16.json`

## 1. 結論

- **Global2 是此 Pilot 最穩定的 Case-RAG 基準**：S1、S2、S3 均高於同一模型的 Baseline，Top-1 分別增加 **6.33、3.67、3.33 個百分點**。
- **S2 + Global2 為最高絕對 Top-1 85.33%（256/300）**；S1 + Global2 改善幅度最大，從 233/300 提升至 252/300。
- 事先設定的配對策略 **Paired2 在三個模型均低於 Global2**，目前缺乏配對檢索機制的增量證據。
- 反事實實驗顯示，**歷史來源的證型標籤影響模型選擇**。隱藏或故意調換來源標籤會降低多組模型成績。這支持需要進一步排除「直接利用檢索病例標籤」的捷徑。
- 本輪為 300 筆非分層 Dev Pilot，僅涵蓋 56/148 類證型。宜使用 Top-1 的個案配對檢定決策；長尾、正式 148 類 Macro-F1 主張需要完整 Dev 確認。

## 2. 主要比較：Global2 vs 原始 Jeff

| 指標 | S1 | S2 | S3 |
|---|---:|---:|---:|
| 原始 Top-1（正確數） | 77.67%（233） | 81.67%（245） | 81.00%（243） |
| Global2 Top-1（正確數） | **84.00%（252）** | **85.33%（256）** | **84.33%（253）** |
| Top-1 增益，百分點 | **+6.33** | **+3.67** | **+3.33** |
| Rescue / Break | 23 / 4 | 16 / 5 | 15 / 5 |
| McNemar exact p，未校正 | 0.000311 | 0.026604 | 0.041389 |
| 95% 群組 Bootstrap，增益百分點 | [+3.01, +9.04] | [+0.67, +6.67] | [+0.67, +6.27] |
| 三次 Global2 比較 Holm 校正 p | **0.000932** | 0.053207 | 0.053207 |
| 排除同文後 Baseline（267 筆） | 74.91% | 79.78% | 78.65% |
| 排除同文後 Global2（267 筆） | 82.40% | 83.52% | 82.77% |
| 排除同文後增益，百分點 | **+7.49** | **+3.75** | **+4.12** |
| Baseline → Global2，Macro-F1（148 固定類別） | 19.09→23.72 | 22.23→24.28 | 20.88→24.00 |

以上 p 值的 Holm 校正僅涵蓋「三個模型、Global2 對各自 Baseline」三項檢定；完整探索性多條件比較需要更廣的多重檢定控制。本批三模型使用**相同 300 筆 Dev 病例**，不可視為 900 筆獨立資料。

## 3. 檢索策略優劣

| 模型 | Global2 | Balanced2 | Paired2 | Random2 |
|---|---:|---:|---:|---:|
| S1 Top-1 | **84.00%** | 82.00% | 81.33% | 80.33% |
| S2 Top-1 | **85.33%** | 84.67% | 85.00% | 83.00% |
| S3 Top-1 | **84.33%** | 82.33% | 82.67% | 82.67% |

Paired2 − Global2：S1 −2.67 pp（未校正 McNemar p=0.0386）、S2 −0.33 pp（p=1.0）、S3 −1.67 pp（p=0.2266）。Paired2 對一般 Global2 的優越性假設沒有得到支持。

## 4. 反事實：來源標籤的作用

以下皆相對各模型的 Paired2：

| 操作 | S1 ΔTop-1 | S2 ΔTop-1 | S3 ΔTop-1 |
|---|---:|---:|---:|
| 隱藏來源證型標籤（labelhide2） | −3.67 pp | −3.00 pp | −1.67 pp |
| 調換來源證型標籤（labelswap2） | −3.00 pp | −3.33 pp | −2.00 pp |
| 調換標籤且反轉來源順序（doubleflip2） | −4.67 pp | −4.33 pp | −5.00 pp |
| 反轉來源順序（orderflip2） | +1.00 pp | −0.33 pp | +0.33 pp |
| 來源歸因防護提示（sourceguard2） | +0.67 pp | −1.67 pp | −1.33 pp |

來源標籤擾動一般比調換排序的影響大，尤其 doubleflip2 在三個模型均退步。該測試故意偽造**檢索來源病例的標籤**；只能用於來源敏感度研究，不能當作診斷方法。現有結果可支持模型受來源標籤顯著影響，不能直接推論模型已正確運用醫案中的症狀與病機。

## 5. 醫案長度與推論成本

完整醫案 FullCase2 相對 Paired2 的 Top-1 差異：S1 +1.33 pp、S2 +0.33 pp、S3 0.00 pp；三組對照的 McNemar p 均未顯示明確優勢。

三模型的推論時間非常接近，平均值約如下：

| 條件 | 平均每病例推論 | p50 延遲 | 平均 Prompt Tokens |
|---|---:|---:|---:|
| Baseline | 約 174 ms | 約 164 ms | 約 742 |
| Global2 | 約 243 ms | 約 229 ms | 約 1,162 |
| Paired2 | 約 243 ms | 約 229 ms | 約 1,161 |
| FullCase2 | 約 347 ms | 約 301 ms | 約 1,691 |

Global2 推論平均約比 Baseline 多 69 ms（約 +40%），FullCase2 約比 Global2 多 104 ms（約 +43%）。量測範圍為 **Jeff `decide` 的單例 GPU 推論與 tokenization wall-time**，排除模型權重載入、BM25 檢索與服務端到端延遲。載入 Jeff 權重所需約 43 分鐘，不屬於上述單例延遲。

## 6. 資料限制與研究風險

- 官方 Dev 共有 5,486 筆，本次僅抽樣 300 筆。
- 300 筆共涵蓋 **56/148 個 gold 證型**，缺少 92 類；其中 25 類只有 1 筆 gold。固定 148 類 Macro-F1 在此樣本上的理論上限為 **37.84%**。避免與完整 Dev 文獻的 Macro-F1 直接比較。
- **33/300** 筆與 Train 存在標準化後完全同文，**2 筆** Train/Dev 同文但 gold 不同，**2 筆**跨 Train/Dev 患者 ID 重疊。排除 33 筆後增益依然存在，但仍須評估近似重複及患者層級獨立性。
- 檢索來源為 Train，沒有使用官方 Test 或 Query gold 建立模型輸入；正式論文須保留此來源稽核與排除重複病例的敏感度分析。

## 7. 下一步優先順序

1. **CPU-only 標籤捷徑基準**：僅用已檢索來源病例的證型與 BM25 排名，建立不依賴 Jeff 的投票／排序基準，測試 Global2 的增益有多少可被來源標籤直接解釋。
2. **逐病例錯誤與醫案敏感度分析**：使用 H200 已儲存的 `data/case_rag/*/scores/*/*.jsonl` logits，統計 Global2／Paired2／Baseline 的交集、增益來源及錯誤類別。九份彙整 JSON 只有聚合指標，尚不足以執行完整個案分析。
3. **預先鎖定方法後再驗證**：先解決來源標籤捷徑、類別覆蓋與資料重複，之後才用完整 5,486 Dev 做配對統計及 148 類 Macro-F1；未定稿前保留官方 Test 封存。
4. **技術定位**：Global2 應視為有競爭力的簡易 Case-RAG 基線。若論文要主張技術原創性，需要針對「來源標籤可靠性／相互矛盾證據／臨床證據可辨識度」提出有實驗支撐的新方法。

報告由 `scripts/analyze_case_rag_archive.py` 以 CPU 自動檢查九份來源 JSON 與各組共享 Baseline／Paired2 數值，沒有新模型訓練或 H200 推論。
