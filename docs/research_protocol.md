# TCMDiscern 研究定稿與實驗規範

**定稿日：2026-11-11｜狀態：已鎖定｜適用範圍：TCM-SD 148 類證型辨別實驗**

本文件是實作、後續模型訓練及 IEEE 論文撰寫的共同依據。若後續要更改研究設計，應新增明確的決策紀錄，保留本次結果的完整可追溯性。

## 1. 核心研究問題

> 在固定的中醫臨床病例資料與官方切分下，BM25／Embedding／Hybrid 能找出多少正確的候選證型？如何透過 Gemma 4 31B + LoRA 在少量候選間辨別，並在候選覆蓋、罕見證型準確率與推論成本之間選擇 K？

優先研究 **TCM-SD 的 148 類單標籤證型分類**。西醫病名、中醫病名及其他診斷任務可做後續擴展，不將其混入這次主基準。現有 819／78 類多標籤研究集為另一個任務，單獨報告、不得與 TCM-SD 分數混算。

**固定決策：不進行重複病歷刪除、不合併病例、不依文字相似度或 user_id 排除、不重新切分、不修正官方標籤。** 對完全相同文字卻有不同標籤的資料，也照原標籤保留。正式評分分母固定為官方切分的完整筆數。

決策理由：維持與使用 TCM-SD 官方切分的公開研究之可比性。**其他文獻未說明去重程序，只能記為「未明確報告」，不能據此宣稱作者有或沒有去重。** 本研究的可比性建立於實際沿用公開切分與公開欄位設定；若各研究的輸入、模型或指標不同，仍需各自註明。

已知重複與衝突必須如實揭露，不能因此聲稱研究具備無洩漏的患者泛化估計。重複資料可能使官方切分評估偏樂觀，屬正式論文的限制。後續不再把「去重子集」當成正式主實驗，也不因看到 Dev/Test 成績而變更切分政策。

## 3. 輸入與標籤界線

- 病例查詢文字：`chief_complaint` 主訴、`description` 病情敘述、`detection` 四診資訊。
- Train 病例的 `norm_syndrome` 可用於建立 **病例 → 證型** 關聯、訓練監督及候選分數彙整。
- Dev 的 `norm_syndrome` **只在排名產生後**用於 Recall、Macro Recall、模型 Top-1 與 Macro-F1 評分。
- `syndrome` 原始標籤、`lcd_id`、`lcd_name`、`user_id` 和其他診斷答案不進入病例查詢、Embedding 輸入或 LLM Prompt。
- 每個檢索排名要包含**互不重複的證型標籤**，不能把不同病例命中同一證型當成多個候選。
- 訓練 LoRA 時，與病例相同的其他真實標籤或同義詞不可直接當負例；需要獨立的標籤語意檢查。
- 任何正式 Test 內容不得參與難負例挖掘、閾值選擇、索引建立、Prompt 搜尋或 LoRA checkpoint 選擇。

## 4. 已完成的實驗與固定方法

**狀態：只有 BM25 候選檢索基準完成，尚無 Gemma、LoRA、Embedding／Hybrid 的 TCM-SD 新實驗分數。**

- 43,180 筆完整 Train 作 BM25 病例索引；5,486 筆完整 Dev 作查詢，沒有排除任何樣本。
- 中文連續文字用 **Bigram 字元詞**，英數文字保留詞元；`CountVectorizer(min_df=2)`。
- BM25：`k1=1.5`、`b=0.75`、`idf=log1p((N-df+0.5)/(df+0.5))`；查詢字詞以 0／1 是否出現計分。
- 同一證型的多個訓練病例，取**最高 BM25 病例分數**作該證型分數；每筆查詢產生至多 50 個互異證型排名；分數相同以穩定排序處理。
- 使用 **全部 5,486 筆 Dev** 計算原始 Recall@1～50。
- Micro Recall@K = Dev 中正確證型出現於前 K 名的病例比例。
- Macro Recall@K = 148 個證型各自 Recall@K 的**等權平均**；Macro Recall 與 Macro-F1 並非同一指標。
- Recall 隨 K 增加單調不減，使用二分搜尋找達到特定 Micro／Macro 門檻的**最小** K。二分搜尋不對任何病例作刪除，也不修改候選排名。

詳細數字與搜尋路徑：[BM25 自動 K 實驗報告](auto_k_experiment.md)。全部 1～50 曲線、命中病例數、148 類別統計及完整搜尋步驟：[機器可讀實驗快照](../experiments/bm25_dev_official_2026-11-11.json)。

## 5. 下一階段實驗設定（預先凍結）

| 項目 | 設定／驗收 |
| --- | --- |
| 主要 LLM | Gemma 4 31B-it，確認實際模型版本及 H200 環境後再啟動 |
| 微調 | LoRA；隨機／BM25 難負例／混合負例作消融 |
| 主候選數 | **K=17**：本輪 Dev Micro Recall 98.65%、Macro Recall 90.49%，是滿足 Macro ≥90% 的最小 K |
| 低 K 對照 | **K=5**：Macro Recall 78.18%，用來比較少數類別的不足 |
| 高 K 對照 | **K=35**：Macro Recall 95.73%，用來檢查額外候選是否改善最終診斷 |
| K 搜尋 | Recall 用二分搜尋；Gemma 最終 Top-1 可能非單調，需使用 Dev **實測、區間探索、必要時鄰域補測** |
| 模型比較 | BM25 Top-1、Embedding Top-1、Hybrid Top-1、Gemma Zero-shot、Gemma 直接 148 類分類、LoRA 重排序 |
| LoRA 訓練資料 | 由全部官方 Train 構造；訓練候選應以 Train 內部 OOF 產生，避免病例本身被檢索為最近鄰 |
| 選模依據 | **Dev Top-1、Macro-F1**，搭配條件準確率、延遲與記憶體；不得用 Test 選模 |
| 正式 Test | 完整 5,486 筆；待方法固定後一次性評分並揭露已知重複情況 |
| 統計報告 | 檢索的 Micro/Macro Recall@K，模型的 Top-1、Macro-F1，總筆數、各類別 support、信賴區間、耗時、顯存與超參數 |

**目前 K=17 是預先設定的 Gemma 第一輪主值，不代表 Gemma 最佳 K。** 後續若 Gemma 在 K=35 或其他 K 的 Dev Top-1、Macro-F1 更佳，可依預先寫明的選模規則選擇；每次變更都記錄原因和比較結果。

## 6. 結果管理

1. `data/`：原始病例、完整逐筆候選及 Dev 金標、本機運行報表，**Git 不提交**。
2. `experiments/`：只有彙整後統計的研究快照，可提交 Git；不包含病例文字、user_id 或逐筆測試答案。
3. `docs/`：方法、決策、資料來源、完整可理解的數值、限制與後續實驗計畫。
4. 每個新實驗要記錄：研究日期、資料分母、來源、切分規則、特徵欄位、索引方法、模型、負例策略、K、超參數、版本、硬體、耗時、所有基準分數、逐類別分數、測試狀態及與對照方法的差異。
5. 尚未執行的實驗一律標為**未測**，不把 Recall 上限當作 Gemma Top-1 成績，也不把其他資料集（如 819 筆）分數混入 TCM-SD 成績表。

## 7. 對論文可直接使用的資料處理說明

> 本研究使用 TCM-SD 官方公開的訓練、驗證與測試切分，分別含 43,180、5,486 與 5,486 筆病例。為保持與使用相同公開基準之既有研究的可比性，本研究保留官方提供的全部樣本與標籤，不進行去重、排除重複患者或重新切分。資料稽核發現，訓練集與驗證集之間有 529 筆完整臨床輸入文字相同的病例，訓練集與測試集之間有 553 筆；其中分別有 20 與 23 筆出現標籤衝突。這些資料均予以保留，並將可能導致未見患者泛化表現被高估列為研究限制。模型建立與選擇只使用官方訓練及驗證資料，最終測試集保留作一次性正式評估。
