## B. 評分定義

- **Micro Recall@K** = 完整 Dev 中正確證型位於前 K 個互異候選的病例數 / 5,486。
- **Macro Recall@K** = 148 個證型各自 Recall@K 的算術平均；罕見類別與常見類別等權。
- **遺漏病例** = Dev 中標籤仍在 K 個候選之外的病例數。
- **Recall@K** 是檢索器的候選涵蓋率；若模型只能從候選中選一個答案，它也是最終 Top-1 的理論上限。**不是 Gemma 最終 Top-1，也不是 Macro-F1。**

## D. 二分搜尋：如何自動找 K

因為固定候選排序的 Recall@K 對 K 單調不減，可用 `K=1…50` 二分搜尋找達到指定 Recall 門檻的最小候選數。此處「測下一個 K」只重新讀取已保存的候選排名，**不用重新建立 BM25 索引**。

| 指標 | 要求 | 最小 K |
|---|---:|---:|
| Micro Recall | ≥80% | 2 |
| Micro Recall | ≥85% | 2 |
| Micro Recall | ≥90% | 3 |
| Micro Recall | ≥95% | **5** |
| Micro Recall | ≥98% | **12** |
| Macro Recall | ≥80% | 6 |
| Macro Recall | ≥85% | 9 |
| Macro Recall | ≥90% | **17** |
| Macro Recall | ≥95% | **34** |
| Macro Recall | ≥98% | **K≤50 無解**（K=50 時為 97.00%） |

### 搜尋歷程範例：Micro Recall ≥95%

```text
K=25 → 99.07%，向小 K 搜尋
K=12 → 98.16%，向小 K 搜尋
K= 6 → 96.32%，向小 K 搜尋
K= 3 → 92.75%，向大 K 搜尋
K= 4 → 94.57%，向大 K 搜尋
K= 5 → 95.46%，找到最小 K
```

### 搜尋歷程範例：Macro Recall ≥90%

```text
K=25 → 93.11%，向小 K 搜尋
K=12 → 88.58%，向大 K 搜尋
K=18 → 90.97%，向小 K 搜尋
K=15 → 89.58%，向大 K 搜尋
K=16 → 89.91%，向大 K 搜尋
K=17 → 90.49%，找到最小 K
```

### 搜尋歷程範例：Macro Recall ≥95%

```text
K=25 → 93.11%，向大 K 搜尋
K=38 → 95.89%，向小 K 搜尋
K=31 → 94.66%，向大 K 搜尋
K=34 → 95.25%，向小 K 搜尋
K=32 → 94.67%，向大 K 搜尋
K=33 → 94.88%，向大 K 搜尋
→ K=34
```

其餘目標的所有中間結果、每一步使用的 K／Recall／搜尋方向，已保存在機器可讀快照。

## E. 當時依 Recall 提出的 K=5、17、35 參考點（後續已更新為全 K 實驗）

| K | Micro | Macro | 實驗定位 |
|---:|---:|---:|---|
| **5** | 95.46% | 78.18% | 低候選對照 |
| **17** | 98.65% | 90.49% | **主要 Gemma LoRA 設定**：滿足 Macro Recall ≥90% 的最小 K |
| **35** | 99.54% | 95.73% | 高涵蓋率對照，觀察是否真的改善難辨證型 |

K=5→17：Micro 增加 3.19 個百分點；Macro 增加 12.31 個百分點。K=17→35：Micro 增加 0.89 個百分點；Macro 增加 5.24 個百分點。由此可見增加 K 對少數類別的收益較顯著。

**2026-11-11 後續決策：Gemma 的 K=1～35 全部列入正式評估，K=17 僅保留歷史分析用途。** Gemma Top-1 可能隨選項增加而下降，不保證單調、也不保證單峰，因此不能直接把「往大或往小」的簡單二分搜尋拿來求 Gemma Top-1 最大值。需實測 Dev Top-1／Macro-F1，探索有潛力的區間並做必要補測，再把 K 與模型定案。

## G. 檔案、版本、重現方式

- Python：**3.12.13**，Linux；**NumPy 2.5.4、SciPy 1.18.1、scikit-learn 1.9.1**。依賴以 [uv.lock](../uv.lock) 鎖定；實際環境版本及原始檔案位元組數也保存在公開快照。
- 計算時間：**22.36 秒**，含 BM25 建索引及 Dev 5,486 筆檢索；CPU，**不含 LLM 推論**。
- 原始 TCM-SD 檔案保留於本機 `data/tcm-sd/`，Git 不提交。
- 完整候選 `data/candidates/bm25_dev.jsonl` 包含逐筆金標，Git 不提交。
- `data/reports/bm25_binary_k_dev.json` 是完整原始 Dev Micro/Macro 1～50 曲線及搜尋紀錄，Git 不提交。
- `data/reports/tcmsd_audit.json` 是全量資料的重複與標籤稽核，Git 不提交。
- **公開資料快照** `experiments/bm25_dev_official_2026-11-11.json` 保留全 K 命中數、曲線、二分搜尋歷程、前 50 命中排名分布、148 類別的訓練／驗證 support 與多個 K 的各類別召回率；**不含任何逐筆病例文字、患者 ID 或逐筆答案**。

```bash
uv sync --python 3.12 --dev
uv run python scripts/fetch_tcmsd.py
uv run python scripts/audit_datasets.py

# 固定完整 Dev，不做任何去重或排除
uv run python scripts/auto_k_bm25.py --max-k 50 --targets 0.80 0.85 0.90 0.95 0.98

# 以逐筆候選重新驗證官方分母與全部統計，並封存公開彙整
# 首次執行會建立快照；既有快照不可直接覆寫
uv run python scripts/freeze_bm25_results.py

uv run pytest -q
uv run ruff check .
```
